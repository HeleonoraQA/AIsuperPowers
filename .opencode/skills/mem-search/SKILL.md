## Когда применять

- Перед задачей, где возможны уже принятые решения (архитектура, схема данных, CLI).
- При восстановлении контекста после перерыва.
- После принятия значимого решения — чтобы записать его в память.

## Поиск

1. `search` с `query` и `project: "AIsp"` — получить индекс с ID.
2. `timeline` с `anchor: <ID>` — посмотреть контекст вокруг нужной записи.
3. `get_observations` со списком ID — прочитать только отобранные записи.

Не читай все записи подряд; `timeline` и `get_observations` — только для
результатов, отобранных на шаге 1.

## Запись

- Найденный факт, который меняет работу, сохранить через `save_memory`
  (`project: "AIsp"`): одно решение — одна запись.
- Перед записью проверить дубли через `search`.
- Долгоживущее решение продублировать в `docs/architecture.md`
  (таблица «Решения и условия пересмотра»), историю — в `docs/progress.md`.

## Ограничения

- Секреты, ключи и содержимое `.env` в память не писать.
- Непомеченное как проверенное не записывать.
- Память не заменяет чтение кода и тестов.
