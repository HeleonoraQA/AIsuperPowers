# AGENTS.md — Правила работы AI-агента

Этот файл является главным источником истины для AI-агента. Строго следуй этим инструкциям при выполнении любых задач.

## 1. О проекте
Учебный CLI-проект «Recipe Finder» (папка `AIsuperPower`): подбор блюд из имеющихся продуктов.
Стек определён: Python 3.11+ (проверено на 3.13), в рантайме только stdlib; `pytest` и `ruff` — dev-инструменты. Git не подключён по решению пользователя.
**Правило:** Не добавляй новые зависимости и библиотеки без явного на то требования в задаче.

## 2. Контекст и документация (Path-Scoped Rules)
Перед выполнением любой задачи агент ОБЯЗАН ознакомиться с контекстом:
- **Перед началом любой задачи:** Прочитай `docs/plan.md` (глобальный план).
- **Если задача затрагивает границы модулей/компонентов:** Прочитай `docs/architecture.md`.
- **Для восстановления контекста после перерыва:** Прочитай `docs/progress.md` (что уже сделано).
- **Для поиска прошлых решений:** Память Claude-Mem **подключена** (плагин `@ephemushroom/opencode-claude-mem`, воркер `http://localhost:37777`, проект `AIsp`). Порядок: `search` → `timeline` → `get_observations`; значимые решения сохраняй через `save_memory`. Долгоживущие решения дублируй в `docs/architecture.md` (раздел «Решения и условия пересмотра»). Подробности: `rules/claude-mem.md`.

## 3. Рабочий процесс (Superpowers / TDD)
1. **Планирование:** Сначала предложи план действий, не пиши код сразу.
2. **TDD (Test-Driven Development):** Сначала пиши падающий тест, затем код, который его проходит, затем рефактори.
3. **Безопасность:** Не удаляй и не изменяй существующие файлы без явного разрешения.

## 4. Ограничения и обратная совместимость
- **Не меняй формат JSON** (если он где-то используется).
- **Не меняй поведение существующих команд** (CLI, скриптов), если это не является прямым требованием текущей задачи.

## 5. Проверки и линтинг
- **Линтер:** `ruff check . --fix` (запускать автоматически после изменения файлов с кодом `.py`).
- **Тесты:** `pytest` (запускать перед завершением любой задачи, строго по TDD).
- **Форматтер:** `ruff format .` (для приведения кода к единому стилю).
- Запрещено запускать линтер для файлов документации (`.md`, `.json`).

## 6. Завершение задачи
Перед тем как сообщить пользователю о завершении задачи, ты ОБЯЗАН:
1. Посмотреть итоговый diff изменений (убедиться, что ничего лишнего не затронуто).
2. Записать фактические результаты проверок (какие тесты/линтеры запускались и прошли ли они) в файл `docs/progress.md`.

## 7. Правила работы

Полные правила — в `rules.md`, она подключается через `opencode.json` (`instructions`). Кратко:

- Запрещены чтение и правка `.env`, `.env.*`, `*.key`, `*.pem` и `secrets/` (задаются в `opencode.json`: `permissions` + дублирующий слой `policies`).
- Без подтверждения разрешены только: `pytest *`, `ruff check *`, `ruff format *`, `git *` (кроме `git push` — всегда `ask`), `ls *`; всё остальное — `ask`.
- Правки файлов требуют подтверждения.
- Изменения вне проекта — запрещены.
- **Конфигурация OpenCode V2:** `opencode.json` подключает `rules.md` и `rules/python.md`
  через `instructions`; плагины задаются одним массивом `plugins` (ключ `plugin` — устаревший V1).
  Навык `checkpoint` лежит в `.opencode/skills/checkpoint/SKILL.md`: только этот путь
  V2 обнаруживает автоматически, корневой `skills/` не сканируется.
  Привязка правил к `*.py` через Cursor-фронтматтер (`globs`) в V2 не поддерживается —
  `rules/python.md` подключается глобально, как и `rules.md`.
- Меняя правила, права или структуру проекта — обновлять `AGENTS.md`, `docs/architecture.md` и `docs/progress.md`.
