# Recipe Finder

CLI-приложение для подбора блюд на основе имеющихся продуктов. Находит подходящие рецепты, фильтрует по способу приготовления и выводит меню из 1–3 блюд.

## Особенности

- **Поиск по ингредиентам** - введите список продуктов, которые есть дома
- **Полное/частичное совпадение** - по умолчанию ищет блюда, для которых есть все ингредиенты
- **Фильтр по способу приготовления** - `steam` (на пару), `oven` (в духовке), `stove` (на плите)
- **Сохранение ингредиентов** - автоматически сохраняет введённый список в `data/ingredients.json`
- **Только stdlib** - без внешних зависимостей
- **TDD-подход** - 49 тестов покрывают все модули

## Использование

Подробная инструкция пользователя — [`docs/USER_GUIDE.md`](docs/USER_GUIDE.md).

Кратко:

### Интерактивный ввод
```bash
python -m recipe_finder
# Затем введите ингредиенты через запятую
```

### С аргументами
```bash
# Поиск по ингредиентам
python -m recipe_finder --ingredients "картофель, масло, соль"

# С фильтром по способу приготовления
python -m recipe_finder --ingredients "яйцо, молоко, масло" --method stove

# Частичное совпадение (разрешить нехватку ингредиентов)
python -m recipe_finder --ingredients "картофель, масло" --min-match-ratio 0.5

# Ограничить количество результатов
python -m recipe_finder --ingredients "овощи" --min-match-ratio 0.3 --limit 5
```

### Аргументы CLI

| Аргумент | Описание | По умолчанию |
|---|---|---|
| `--ingredients` | Список ингредиентов через запятую | Интерактивный ввод |
| `--method` | Фильтр по способу: `steam`, `oven`, `stove` | Без фильтра |
| `--limit` | Максимальное количество блюд | `3` |
| `--min-match-ratio` | Минимальный порог совпадения (0-1) | `1.0` (полное совпадение) |
| `--recipes` | Путь к файлу рецептов | `data/recipes.json` |
| `--store` | Путь к файлу сохранённых ингредиентов | `data/ingredients.json` |

### Superpowers-фреймворк
В проекте подключён фреймворк **[Superpowers](https://github.com/obra/superpowers)** (`superpowers@git+https://github.com/obra/superpowers.git` в `opencode.json`).

- **TDD** - агент следует подходу Red-Green-Refactor: сначала пишет падающий тест, затем минимальную реализацию, потом рефакторинг.
- **Планирование** - перед написанием кода агент формирует план действий, учитывая текущий этап из `docs/plan.md` и ограничения проекта.
- **Ревью** - фреймворк помогает проводить осознанное ревью изменений: проверка соответствия архитектуре, слоистой структуре, тестовому покрытию и правилам из `AGENTS.md`.

Используется в связке с TDD-подходом проекта и обязательными проверками `ruff` + `pytest`.
