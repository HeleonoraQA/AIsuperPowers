# Plan.md — План разработки проекта

## 1. Концепция и цель (Elevator Pitch)
**Идея:** Приложение (или скрипт) для формирования списка блюд на основе имеющихся у пользователя продуктов. 
**Цель:** Упростить процесс планирования готовки, предлагая рецепты, которые можно приготовить из того, что уже есть дома, с фильтрацией по способу приготовления и времени.

## 2. Scope (Границы проекта)
### Что входит в MVP (Этап 1):
1. **Ввод ингредиентов:** Возможность запросить у пользователя список имеющихся продуктов.
2. **Сохранение:** Сохранение введенного списка в локальный файл формата `JSON`.
3. **Поиск блюд:** Алгоритм поиска блюд, которые можно приготовить из этого списка (учет полного или частичного совпадения ингредиентов).
4. **Формирование меню:** Вывод списка из 1–3 блюд с указанием категории приготовления (на пару, в духовке, на плите).

### Что входит в Этап 2 (Post-MVP):
1. **Время приготовления:** Добавление и вывод информации о времени готовки для каждого блюда.

### Что НЕ входит (Out of Scope):
- Сложные графические интерфейсы (начинаем с CLI/консоли).
- Интеграция с внешними API (пока используем локальную базу рецептов).
- Авторизация пользователей (проект для личного использования).

## 3. Основные этапы (Roadmap)
- [x] **Этап 1. Инициализация:** Выбор стека (язык, линтер), настройка структуры папок, создание базового JSON-файла с рецептами.
- [x] **Этап 2. Ввод и сохранение:** Реализация функции запроса ингредиентов и записи их в `ingredients.json` (с соблюдением строгого формата).
- [x] **Этап 3. Ядро логики (Поиск):** Написание алгоритма, который берет список продуктов и находит подходящие блюда.
- [x] **Этап 4. Вывод меню:** Реализация фильтрации по способу приготовления (пар, духовка, плита) и формирование списка 1-3 блюд.
- [ ] **Этап 5. Доработка (Post-MVP):** Внедрение поля `cooking_time` в базу рецептов и его вывод в консоль.

## 4. Неизвестные и риски (Discovery)
На этапе исследования (Discovery) агенту предстоит выяснить и предложить решения по следующим вопросам:
1. **Выбор стека:** На каком языке лучше реализовать (Python, JS/Node.js)? Что проще для работы с JSON?
2. **Структура базы рецептов:** Как лучше организовать локальный JSON с рецептами, чтобы поиск работал быстро? 
3. **Алгоритм поиска:** Как учитывать «частичное совпадение» (если у пользователя нет 1 ингредиента, предлагать ли блюдо)?
4. **Тестирование:** Как писать TDD-тесты для алгоритма поиска, чтобы они не зависели от случайного выбора блюд?

## 5. Ограничения
- Работаем только с локальными данными (без внешних баз данных).
- Строгое соблюдение формата JSON (запрещено ломать существующую структуру).
- Добавление новых зависимостей только с разрешения пользователя.
