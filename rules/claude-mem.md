# Память Claude-Mem

Память проекта **подключена** и доступна агенту. Отдельного `docs/memory.md` нет:
долгоживущие решения живут в `docs/architecture.md`, история работы — в
`docs/progress.md`, а быстрый поиск по прошлым сессиям — в Claude-Mem.

## Как искать (обязательно перед задачей)

Три шага, без пропусков:

1. `search` — индекс с ID и заголовками (`query`, `limit`, `project`).
2. `timeline` — контекст вокруг выбранного ID (`anchor`).
3. `get_observations` — полный текст только по нужным ID.

Не тяни все записи подряд и не подменяй поиск чтением всей истории: `timeline`
и `get_observations` вызываются только для отобранных результатов.

## Что сохранять

- Принятые решения и их условия пересмотра (дублировать в `docs/architecture.md`).
- Исправления ошибок, которые уже случались, — чтобы не повторять.
- Состояние незавершённой работы при передаче сессии.

Инструмент: `save_memory` (`project: "AIsp"`), одно решение — одна запись,
формулировка факта, а не рассуждения. Перед записью проверить дубли через `search`.

## Чего не делать

- Не писать в память секреты, ключи, содержимое `.env` и персональные данные.
- Не считать память источником истины для кода: код и тесты важнее записи.
- Не помечать в памяти непроверенное как проверенное.
